bloop is strict: a mistake stops the script with a message that says what and where, instead of carrying on with a guess.

Compile errors

Found before anything runs: syntax, an unknown name, a name declared twice (shadowing), assigning to a constant, an import that can't be found. Nothing of the program runs.

let total = 0;
totl += 1;
Output:
unknown identifier: totl
at: 2:1

Runtime errors

Found while it runs, they end the script (or, in a program running it, the call that was running): catch can't catch them. The message has a stack trace: where it happened, then the calls that led there.

fn second(list) {
	return list[5];
}
fn first() {
	return second([1, 2]);
}
first();
Output:
runtime error


out of bounds index [5]

at [2, 16]
return list[5];
           ^
at [5, 18]
return second([1, 2]);
             ^
at [7, 6]
first();
     ^

Standard functions

A standard function used wrongly (an argument of the wrong type, a negative count) is a runtime error. What can fail when everything is right returns undefined instead: std.fs.read of a file that isn't there, std.json.parse of text that isn't JSON, std.string.parse_int of text that isn't a number.
